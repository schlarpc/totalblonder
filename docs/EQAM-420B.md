# The Blonder Tongue EQAM-420B

What this project knows about the modulator it feeds, in short. The details, with evidence,
are in [`notes/`](notes/): the device survey (`device.md`), the firmware (`firmware.md`), the
manual (`manual.md`), outside research (`research.md`) and the configuration defects
(`corruption-48.md`).

## What the box is

- **An IP-to-QAM modulator, not an encoder.** It takes MPEG-2 transport streams over UDP or
  RTP on two GigE ports and modulates them onto 16 QAM carriers (4 RF modules × 4 adjacent
  carriers). It does not transcode.
- **An FPGA design with a Nios II soft CPU** running uClinux 2.6.26. The stream path is in the
  FPGAs: one input FPGA per GigE port, carriers 1–8 on GIGE1 and 9–16 on GIGE2. Linux does
  only the configuration, IGMP joins and the web interface.
- **Software 1.1.13**, the latest and only published build.
- **Management** is Boa CGI forms, plus FTP and telnet as root. Firmware updates carry no
  signature or checksum.
- **Reporting** is the web pages and syslog. There is no SNMP agent in the image, although the
  admin page has SNMP fields.

## Input contract

| | SPTS mode | MPTS mode |
|---|---|---|
| Inputs | 64 single-program streams, 4 per carrier | 16 multi-program streams, 1 per carrier |
| Programs | 1 video + at most 1 audio each | At most 6 per carrier, 1 video + at most 3 audio each |
| PAT/PMT, PIDs | Regenerated and remapped by the box | Passed through |
| PSIP (channel numbers, names) | Generated by the box from its web interface | Passed through |
| Program guide | Not supported | Passed through |
| Second audio | Not possible | Possible |

Common to both: at most 38.8 Mbit/s per carrier (256-QAM Annex B), MPEG-2 or H.264 video, AC-3
audio, multicast with IGMP v2/v3 or unicast. The box inserts and deletes null packets and
corrects PCR but does no rate control: a carrier sent too fast breaks up on the TV.

totalblonder uses MPTS mode: it sends each carrier's whole transport stream, tables included.

## Defects that matter

Three defects in the firmware's configuration handling are confirmed in disassembly
([`notes/corruption-48.md`](notes/corruption-48.md)):

- **A:** saving one RF module's QAM page writes RF-channel bytes into the wrong table. Saving
  all four modules in order, in MPTS mode, is safe; the supervisor only writes that way.
- **B:** at boot, in Automatic configuration mode, the box overwrites its stream table from a
  flash file that it parses incorrectly. Set Manual mode once, by hand.
- **D:** a per-stream program table in `mux_sync` grows every 30 seconds while streams are
  present and is not cleared. Its consequences have not been observed yet; the supervisor
  alarms when the box has run longer than a set time since its last boot.

## Rules for working with the box

- Never submit the admin page (`admin.cgi`) except by hand, deliberately: it holds the network
  settings, passwords, reboot, flush and delete. These GET URLs act at once: `admin.cgi` with
  `btnReboot`, `btnFlush` or `btnDeleteConfig` in the query. `tools/eqam_get.sh` refuses any
  URL containing `btn`, and the supervisor's request screen refuses every admin request except
  one bare read.
- A changed GigE address reboots the box right after it is saved.
- A wrong or ASCII-mode firmware upload can brick the unit.
- **Recovery:** hold the front-panel IP RESET button for about 10 seconds, power-cycle, and
  reach the box at 172.16.70.1 on the 10/100 control port with the vendor's default logins.
- Take an EEPROM dump before any change that writes it (`tools/eedump/`).
