# V1 running notes: the conformance verifier (`tb-m2v-verify`)

Working log of package V1. Newest entries first within a section.

## State

- Crate `crates/tb-m2v-verify`: library (sans-io, `verify(&[u8], &Options) -> Report`) and
  CLI. Tables generated by `tools/gen_tables.py` from the H.262 text extraction
  (`work/standards/ITU-T_H.262-200002-S.txt` in the main checkout).
- Rule catalog lives in `src/rules.rs`; `notes/m2v-conformance-rules.md` is generated from
  it (`tb-m2v-verify --rules-md`) under a hand-written head.
- Streams: `work/streams/nixark/` (302 files copied from nixark, 899 MB, gitignored via
  `work/`), `work/streams/ffmpeg/` (independent encoder), `work/streams/ref/` (our encoder on
  the CPU reference adapter).

## Decisions

1. Independence: nothing under crates/tb-m2v-{syntax,encoder,rate}, crates/tb-m2venc or
   spikes/cuda-mpeg2/src was read while the verifier was written. (One slip: the head of
   crates/tb-m2v-rate/Cargo.toml was printed to copy the manifest layout; it holds no encoder
   logic.) The encoder sources were opened only after the first audit run, to locate causes.
2. No sample reconstruction: no rule needs pixels. The verifier decodes syntax, DC and
   vector predictors, the inverse quantization arithmetic (for saturation), and the VBV.
3. Mismatch control and IDCT are decoder processes, not bitstream rules: cataloged as not
   checkable.
4. Escape for a (run, level) that has a VLC: the text of 7.2.2.3 does not forbid it. Reported
   as S4 note `BLK-ESCAPE-REDUNDANT`.
5. `*.ref.m2v` in the nixark set are not our encoder's (three are empty, one is a cut-off
   reference encode by another encoder); excluded from the audit.
6. Zero bytes after user data are formally user data (6.2.2.2.2), so 3 or more of them break
   6.3.4.1; reported as `UD-ZERO-RUN`.

## Log

- Final audit (verifier at this commit): 298 stored streams, profiles h262-only, a53,
  scte43-64qam, scte43-256qam, each with the operating model: 0 S1, 0 S2. S3:
  `BC-PROGRESSIVE-FPFD` (617 pictures, the 8 `pipe-*` streams with progressive sources),
  `BC-FORMAT` (8 `devin-crop` streams). S4: `CC-608-ORDER`, `BC-COLOR-PREFERRED`,
  `BC-SEQ-INTERVAL`. JSON reports under work/audit/ (gitignored).
- Reference adapter (`tools/ref_cases.sh`, 2 minutes): 27 clean streams without any finding;
  12 known-gap streams trip 13 rules, allowlisted in `tools/known-findings.txt` against
  worklist items 1 to 8. Findings worth knowing: 24 fps sessions underflow the VBV (60 Hz
  label); a fixed-quantizer picture cut at the size limit loses macroblocks; a width of 4096
  writes horizontal_size_value 0; range 40 gives a vertical vector of +128.0.
- Independent encoders: ffmpeg 6.1.6 (local) and 9.0.2 (flake) and mjpegtools 2.2.1 all
  decode; deviations recorded per case in `tools/independent.py`. No field pictures from an
  independent encoder (mpeg2enc -I 2 writes nothing here).
- Tests: `tests/rules.rs` has a detecting stream for every rule marked checked (the
  `coverage` test fails if one is added without); `tests/mutation.rs` overwrites header
  fields in built and encoder streams (set `TB_M2V_VERIFY_STREAMS=dir`) and flips random
  bits (no panic).
- Bugs the tests found in the verifier itself: picture data boundaries for the VBV were
  taken at the picture coding extension instead of the first header (all picture sizes
  shifted); the frame's temporal_reference was the second field's; a slice that failed to
  decode produced a false `SLICE-GAP`.
- Flake: `nix/verify.nix` (checks verify/ref-streams, verify/independent,
  verify/rules-catalog; app verify-streams), three lines in flake.nix.
- First run over the 302 stored streams (profile scte43-256qam, operating model): no S1 or S2
  finding in our encoder's streams.
- ffmpeg mpeg2video trips `PL-BIT-RATE` (bit_rate 0x3FFFF x 400 when no maxrate is given)
  and `VBV-PICTURE-SIZE` (constant-quantizer runs with the default tiny vbv_buffer_size).

## Not done

- Field pictures, dual prime, 16x8 and concealment vectors are exercised only by hand-built
  streams (no independent encoder here produces them).
- The caption channel packet layer (`CC-PACKET`) is cataloged, not checked.
- The gate scripts do not call the verifier yet; the hook is in
  notes/m2v-conformance-findings.md §8.
